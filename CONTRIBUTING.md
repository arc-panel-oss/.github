# Contributing to ArcPanel

Thank you for helping. You don't need to write code to move the project forward.

## Ways to help

- **Report a bug** with the issue form of the repository: your OS, the ArcPanel version, the steps to reproduce and the logs.
- **Translate the panel** on [Crowdin](https://crowdin.com/project/arcpanel).
- **Test pre-releases** on a spare amd64 server with Debian or Ubuntu, and tell us what breaks.
- **Ask and answer questions** in [GitHub Discussions](https://github.com/arc-panel-oss/arcpanel/discussions).

## Pull requests

We welcome issues from everyone. Pull requests need an agreement first:

1. Open an issue that describes the bug or the change, or comment on an existing one.
2. Wait until a maintainer accepts it. ArcPanel has strict architecture rules and release lines, so we agree on the approach before code is written.
3. Branch from `develop`, make the change and add tests for it.
4. Open the pull request against `develop` with a [Conventional Commits](https://www.conventionalcommits.org/) title, such as `fix(mail): …`, and link the accepted issue.

A pull request without an accepted issue is closed with a pointer to the issue form.

Each repository describes its setup, checks and rules in its `README.md` and `AGENTS.md`. The full contributor guide is at [arcpanel.top/contributing](https://arcpanel.top/contributing).

## Conduct and security

Everyone who takes part follows the [code of conduct](CODE_OF_CONDUCT.md). Report security issues privately as described in the [security policy](SECURITY.md), never in a public issue.
